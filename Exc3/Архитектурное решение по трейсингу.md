## Мотивация зачем нам трейсинг

1. Трейсинг позволит отслеживать, сколько времени занимает выполнение каждого этапа обработки запроса (например, API → RabbitMQ → MES → База данных). Он поможет нам выявить компоненты, которые замедляют работу системы.

2. Упроситист отлатку нашей распределенной системы. В такой системе сложно отследить, где именно произошла ошибка. Трейсинг покажет нам полный путь запроса.

3. Анализируя данные трейсинга, можно оптимизировать работу системы, и сократить время обработки запросов и снизив нагрузку на ресурсы.

4. Трейсинг поможет понять, как система ведёт себя под нагрузкой, и спланировать масштабирование.


На текущей архитектуре системы (C4) для трейсинга будут выделены следующие элементы:

#### **Контекст системы (Level 1):**
- **Интернет-магазин:** Отслеживание заказов с момента их создания.
- **CRM:** Контроль за передачей данных между CRM и MES.
- **MES:** Время обработки заказа, расчет стоимости, передача статусов.
- **API:** Управление входящими и исходящими запросами.
- **RabbitMQ:** Передача сообщений между компонентами системы.
- **Базы данных (PostgreSQL):** Время записи и чтения данных, использование ресурсов.

#### Элементы системы:
  - Приложения: Интернет-магазин, CRM, MES.
  - Инфраструктура: RabbitMQ, PostgreSQL.
  - Мониторинговые инструменты: OpenTelemetry, Jaeger.
  
- Основное внимание уделяется следующим компонентам:
  - Входящие запросы в API (HTTP, gRPC).
  - Очереди сообщений RabbitMQ.
  - Операции базы данных PostgreSQL.

## Составьте список данных, которые должны попадать в трейсинг

Данные:
-   ИД пользователя 
-   ИД заказа 
-   ссылка на файл с 3D моделью
-   Дата создания заказа
-   Стоимость заказа
-   Статус заказа  
-   Trace ошибок, возникших в системе

Запросы и время их обработки:
- Время обработки запросов (latency).
- Количество успешных и неуспешных запросов.
- Время записи и чтения в базах данных.
- Загрузка очередей RabbitMQ.

Инфраструктурные
- Загрузка компонентов (CPU, RAM).
- Потерянные сообщения в RabbitMQ.

## Компромиссы

1. Ограниченные ресурсы.

        Внедрение системы трейсинга может потребовать серьёзных вложений: покупка технологий, обучение сотрудников и поддержка системы. Если у компании небольшой бюджет или мало ресурсов, такие затраты могут быть неоправданными. Особенно это касается маленьких компаний или стартапов, где каждый рубль на счету.

2. Технические ограничения

        Иногда внедрить трейсинг просто невозможно из-за старых или неподходящих технологий. Например, если текущее оборудование или программы не поддерживают трейсинг, это может сделать его внедрение слишком сложным или даже нереальным.

3. Организационные сложности

        Если в компании строгая иерархия или постоянные изменения в управлении, внедрить трейсинг будет непросто. Сотрудники могут сопротивляться нововведениям, особенно если они не привыкли к прозрачности или боятся изменений. Это может замедлить или даже сорвать проект.

4. Конфиденциальность и безопасность

        Трейсинг может столкнуться с проблемами, если в компании строгие правила по защите данных. Например, если есть законы, которые ограничивают сбор и обработку личной информации, внедрение трейсинга может оказаться слишком сложным и дорогим. Нужно будет убедиться, что система соответствует всем стандартам и нормам.

## Проработайте аспекты безопасности

1. Аутентификация и авторизация

        Внедрить систему аутентификации (например, через LDAP, Active Directory или OAuth).
        Доступ к системе трейсинга будет только у сотрудников с актуальными учётными записями.Настроить ролевую модель доступа. 

2. Шифрование данных

        Все данные трейсинга должны передаваться по защищённым протоколам (например, HTTPS, TLS).
        Данные в хранилище должны быть зашифрованы (например, с использованием AES-256).

3. Логирование и аудит

        Внедрить систему логирования всех действий в системе трейсинга (кто, когда и что делал).
        Регулярно проводить аудит логов для выявления подозрительной активности.

4. Ограничение доступа к данным

        Настроить доступ к данным на основе принципа минимальных привилегий (каждый сотрудник получает доступ только к тем данным, которые необходимы для его работы).
        Использовать маскирование данных, если в трейсинге передаются чувствительные данные (например, персональные данные клиентов).

5. Защита от атак
        
        Внедрить системы предотвращения атак (например, WAF — Web Application Firewall).

6. Соблюдение нормативных требований
        
        Убедиться, что система трейсинга соответствует всем нормативным требованиям ФЗ
        Проводить регулярные аудиты безопасности.

7. Сегментация сети

        Сегментация сети: Создание отдельных сегментов для разных функций, чтобы ограничить доступ к критическим системам и данным.
